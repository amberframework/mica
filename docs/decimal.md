# Exact decimals and money: `Mica::Decimal128`, `Mica::Currency`, `Mica::Money`

```crystal
require "mica/decimal"        # Decimal128, Currency and Money only
require "mica/decimal/json"   # opt-in: to_json / from_json
require "mica/decimal/yaml"   # opt-in: to_yaml / from_yaml
require "mica/decimal/big"    # opt-in: BigDecimal conversions (links libgmp)
```

`require "mica/decimal"` links no C library: a program that uses it links
only libgc, libiconv and libSystem, like every Mica program
(`scripts/check_linkage.sh` proves it with otool, `nm -u` and the linker
map, against a control that requires `mica/decimal/big`). `require "mica"`
loads the three types too.

## Decimal128

A struct of an `Int128` coefficient and an `Int32` scale from 0 to 38:
the value is `coefficient / 10**scale`, so it holds up to 38 significant
digits, the range of SQL `NUMERIC(38, s)` and C#'s `decimal`.

```crystal
price = Mica::Decimal128.parse("19.99")
rate = Mica::Decimal128.parse("0.0825")
price * rate                          # => 1.649175 (exact, scale 2 + 4)
(price * rate).round(2, :ties_away)   # => 1.65
Mica::Decimal128.new(1).divide(Mica::Decimal128.new(3), 4, :ties_even) # => 0.3333
Mica::Decimal128.parse("12.30") == Mica::Decimal128.parse("12.3")     # => true
```

| Operation | Result scale | When it raises |
|---|---|---|
| `a + b`, `a - b` | the larger scale | `OverflowError` past 38 digits |
| `a * b` | the sum of the scales | `OverflowError` past 38 digits or scale 38 |
| `a.divide(b, scale, mode)` | `scale` | `DivisionByZeroError`, `OverflowError`, `InexactError` (mode `Unnecessary`) |
| `a.round(scale, mode)` | `scale`, or unchanged when already at or below it | `InexactError` (mode `Unnecessary`) |
| `a.rescale(scale, mode = :unnecessary)` | exactly `scale` (raising it pads with zeros) | `OverflowError`, `InexactError` |

Nothing rounds silently: an exact result that does not fit raises
`OverflowError` instead. All four errors descend from
`Mica::Decimal128::Error`; a scale argument outside 0..38 raises
`ArgumentError`.

`<=>`, `==` and `hash` go by value, so `12.30` and `12.3` are equal and
hash the same (the hash drops trailing fraction zeros). `to_s` keeps the
scale (`12.30`, `-0.05`, `0.0000`) and never writes an exponent. Also:
`to_i64` (truncates), `to_f64` (correctly rounded), `zero?`, `negative?`,
`positive?`, `sign`, `abs`, unary `-` and `precision` (the coefficient's
digit count).

### Rounding modes

| Mode | 2.5 | -2.5 | 2.4 | -2.6 |
|---|---|---|---|---|
| `TiesAway` (half up) | 3 | -3 | 2 | -3 |
| `TiesEven` (banker's) | 2 | -2 | 2 | -3 |
| `Floor` | 2 | -3 | 2 | -3 |
| `Ceiling` | 3 | -2 | 3 | -2 |
| `Truncate` | 2 | -2 | 2 | -2 |
| `Unnecessary` | raises `InexactError` | raises | raises | raises |

### Parsing

`Decimal128.parse` reads an optional sign, digits, an optional `.` with
fraction digits and an optional exponent: the text PostgreSQL `numeric`,
MySQL `DECIMAL`, JSON numbers and `BigDecimal#to_s` produce. Trailing
fraction zeros are kept as scale (`"12.30"` has scale 2); an exponent moves
the point (`"1.0e-6"` is `0.0000010`, `"1.2345e+19"` is
`12345000000000000000`). When the written form needs more than 38 digits or
a scale above 38 but the value does not, trailing zeros give way
(`"1.000e-38"` is coefficient 1 at scale 38); otherwise `OverflowError`.
Anything else, including spaces, `NaN` and `Infinity`, raises `ParseError`.
`parse?` returns nil instead of raising.

### No heap allocation

Arithmetic, comparison, hashing, division, rounding and rescaling run on
the stack: 128-bit integers, a 256-bit intermediate of two `UInt128`
halves for products and dividends that need it, and a table of the powers
of ten up to 10**38. `parse` allocates nothing either; `to_s` allocates
only the String. `spec/decimal/decimal128_spec.cr` counts the collector's
bytes over 110,000 operations.

## Currency

`Mica::Currency::TABLE` holds every current ISO 4217 currency (178 codes,
from the list published 2026-09-17): the alpha code, the numeric code and
the minor units (USD 2, JPY 0, BHD 3, CLF 4).

```crystal
Mica::Currency.find("BHD").minor_units # => 3
Mica::Currency.find?("ZZZ")            # => nil
Mica::Currency.find("ZZZ")             # raises Mica::Currency::UnknownError
Mica::Currency.find("XAU").minor_units? # => nil (ISO gives "N.A.")
```

`minor_units` raises `Currency::NoMinorUnitsError` for the codes ISO 4217
gives none (precious metals, SDR, test and fund codes); `minor_units?`
returns nil for them. The table is generated by
`scripts/generate_currency_table.rb` from the snapshot
`scripts/iso4217/list-one.xml`, whose sha256 the script checks.

## Money

```crystal
total = Mica::Money.new("100.00", "USD")
total.split(3).map(&.to_s)               # => ["33.34 USD", "33.33 USD", "33.33 USD"]
total.allocate([70, 20, 10]).map(&.to_s) # => ["70.00 USD", "20.00 USD", "10.00 USD"]
(Mica::Money.new("19.99", "USD") * Mica::Decimal128.parse("1.0825")).round(:ties_away).to_s # => "21.64 USD"
Mica::Money.new(1, "USD") + Mica::Money.new(1, "EUR") # raises Mica::Money::CurrencyMismatchError
```

- `+` and `-` only between equal currencies; `*` by a `Decimal128` or an Int.
- `round(mode)` rounds (and pads) to the currency's minor units.
- `allocate(ratios)` and `split(parts)` return amounts at the minor units
  that add up to exactly the original: proportional shares rounded down,
  then the leftover minor units one each to the largest remainders (the
  earlier part on a tie). A ratio of 0 gets nothing. The amount must
  already sit at the minor units (`Decimal128::InexactError` otherwise).
- `to_s` is plain, `"12.30 USD"`; locale formatting belongs to the view.
- `==` and `hash` go by amount value and currency.

## JSON, YAML and BigDecimal

- JSON writes the plain form as a JSON string (`"12.30"`), so no reader
  turns it into a binary float, and reads a JSON string, or an integer or
  float token parsed from its text (`12.30` keeps its scale).
- YAML writes a plain scalar (`12.30`) and reads any scalar's text.
- `to_big_d` and `Decimal128.new(BigDecimal)` convert exactly; the latter
  raises `OverflowError` when the value needs more than 38 digits.

## Correctness

`scripts/decimal_differential.cr` runs seeded random operations on operands
of up to 38 digits (money shapes, uniform digits and scales, all-nines and
powers of ten, exact ties, exponent texts) against the standard library's
`BigDecimal` and `BigInt`, comparing every digit and scale, and every
overflow, inexact and division-by-zero outcome:

```sh
crystal-alpha build --release scripts/decimal_differential.cr -o bin/decimal_differential
bin/decimal_differential 20261127 1000000   # differences: 0
```

## Vendoring

A library that cannot depend on the Mica shard takes a pinned copy:

```sh
/usr/bin/ruby scripts/vendor_into.rb --commit COMMIT --component decimal --namespace Grant --destination ../grant/src/grant/vendor
```

The component is `src/mica/decimal.cr` and `src/mica/decimal/` (the JSON and
YAML conversions included) without `src/mica/decimal/big.cr`, so the copy
never requires "big"; it needs nothing from `Mica::Core` and uses no
Regex.
